## Э0 — Фундамент репозитория и контур разработки ✅ (2026-07-31)

Подробности — [DEVELOPMENT.md](DEVELOPMENT.md), [OPERATIONS.md](OPERATIONS.md), [QUALITY.md](QUALITY.md).

**Осталось сделать руками** (требует доступов, которых нет у репозитория):
1. Завести секреты в GitHub: `SSH_HOST`, `SSH_USER`, `SSH_KEY`, `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`.
2. Создать два проекта в Cloudflare Pages: `fluenta-marketing`, `fluenta-app`.
3. Прогнать `infra/provision.sh` на сервере и положить `/opt/fluenta/.env`.
4. Направить DNS: `api` и `api-dev` на сервер (DNS-only), `fluenta.wiki` и `app` — на Pages.
5. Создать окружение `prod` в настройках репозитория с правилом ручного подтверждения.

## Э1 — Сквозной путь «код → прод»

Цель: пустое, но настоящее приложение открывается на `fluenta.wiki`, деплой одной командой.

- ✅ `app/` — проект под web + iOS + Android + macOS; дизайн-токены и тема; адаптивный каркас (нижние вкладки → боковая полоса → боковая с подписями) на go_router; заглушки семи разделов; шрифты Source Serif 4 и Inter забандлены; 9 тестов.
- ✅ `backend/` — FastAPI-скелет с `/healthz`, конфигурация через переменные окружения, многоступенчатый Dockerfile с non-root пользователем; 6 тестов, покрытие 100%.
- Осталось: Postgres + pgvector в приложении, Alembic, генерация Dart-клиента из OpenAPI.
- `infra/` — docker-compose (Caddy + api + postgres), провижн сервера (non-root sudo, SSH по ключу, UFW, fail2ban), DNS `fluenta.wiki` → сервер, TLS.
- CI: линт + тесты, генерация Dart-клиента из OpenAPI.
- ⚠️ Вместе с созданием каждой части **раскомментировать соответствующий блок в `.github/dependabot.yml`** — они выключены, пока манифестов нет, иначе Dependabot падает и шлёт уведомления.

## Э2 — Спайки двух главных рисков

Не экраны, а проверки. Делать ДО продуктовых фич — от их результата зависит объём остального.

1. **Читалка во Flutter:** тап и hover по слову, выделение произвольного фрагмента, popover, серифная типографика 17.5–18.5px / 1.72, поведение при переносе строк. Это самая непривычная для Flutter часть.
2. **Голос реального времени:** микрофон → WebSocket → релей → Gemini Flash Live → ответ, с barge-in. Проверить на web и на реальном iOS-устройстве (фоновое аудио, разрешения). Померить задержку с учётом US-West сервера.

## Э3 — Онбординг (3 минуты)

Первый настоящий поток и одновременно вертикальный срез продукта: вопрос о языке → текст 160 слов → тап по фразе (перевод → «почему» → «нельзя просто talked») → пересказ 30 сек → одна правка → aha-экран с кривой забывания → мягкая стена «Сохранить прогресс?». Регистрации нет до конца; «Пока без аккаунта» — прогресс локально. Три лэйаута: телефон 390 / планшет 834 / ПК двухколоночный.

## Э4 — Аккаунты, минуты, гейтинг

Регистрация/вход, JWT, синхронизация локального прогресса. **Учёт голосовых минут и гейтинг тарифов — только на сервере.** Предупреждение перед сессией («займёт ~12 мин из 128, останется 116»), окраска остатка: >30% индиго `#4F46E5`, ниже — янтарный `#F59E0B`.

## Э5 — Читалка целиком

Текст, сохранённые слова, разбор «почему так» (spaCy + spacy-llm), двухуровневый перевод: мгновенный локальный по тапу и глубокий LLM-разбор по выделению.

## Э6 — Тьютор

Пересказ вслух, memory coverage, **правило одной правки**, ошибки → карточки на завтра 09:00. Запись по умолчанию не хранится; тумблер «Сохранить эту запись» (Pro; Free — 1 раз в месяц). Микрофон запрашивается только в момент пересказа + текстовый fallback.

## Э7 — Повторения и Библиотека

FSRS по предложениям (не по словам), Again/Hard/Good/Easy. Библиотека с уровнями и «% знакомых слов», импорт своих текстов.

## Э8 — Прогресс и Профиль

Heatmap вместо streak, «минут речи», уровень + шкала «B2 ≈ IELTS 5.5–6.5 · TOEFL 72–94». Профиль: счётчик минут, журнал расхода, пакеты, тариф.

## Э9 — Paywall и платежи

Web — внешний провайдер; iOS/Android — IAP (см. «Открытый вопрос 2» в [ARCHITECTURE.md](ARCHITECTURE.md)). Единый учёт минут на сервере.
