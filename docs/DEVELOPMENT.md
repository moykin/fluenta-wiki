# Локальная разработка

> Как видеть результат у себя до того, как что-то куда-то выкатывается.

## Один раз после клона

```bash
make hooks     # pre-commit хуки, включая сканер секретов
make db-up     # локальный Postgres + pgvector в Docker
```

Нужны: Flutter (stable), Dart, `uv`, Docker Desktop. Проверка — `flutter doctor` и `docker info`.

## Каждый день

`make` без аргументов покажет весь список. Основное:

| Команда | Что делает |
|---|---|
| `make api` | Backend на `127.0.0.1:8000`, автоперезагрузка. Документация API — `/docs` |
| `make web` | Маркетинг (Jaspr) на `127.0.0.1:8080`, hot reload |
| `make app-web` | Приложение в Chrome, hot reload |
| `make app-macos` | Приложение нативно на macOS |
| `make app-ios` | Приложение на iPhone/iPad или симуляторе |
| `make devices` | Какие устройства сейчас доступны |

Каждая команда — отдельная вкладка терминала. Обычный набор: `make api` + `make app-web`.

## Как смотреть адаптив

Дизайн сделан fluid-вёрсткой, ломаться он может в промежуточных ширинах, а не только на брейкпоинтах.

- **Веб:** DevTools → device toolbar, проверять 390 / 834 / 1280 — те же три ширины, что в макете `Fluenta Responsive QA.dc.html`.
- **Планшет:** `make app-ios` на iPad даёт настоящий, а не эмулированный лэйаут.
- **Рядом с макетом:** откройте соответствующий `design/*.dc.html` в браузере и сравнивайте бок о бок. Макеты открываются двойным щелчком, сервер не нужен.

Перед тем как считать экран готовым — посмотреть его на реальном телефоне. Тач-цели и типографика на устройстве ощущаются иначе, чем в эмуляции.

## Перед push

```bash
make check     # ровно то же, что запустит CI: формат, линт, типы, тесты
make secrets   # сканирование на утёкшие секреты
```

Если `make check` зелёный — CI почти наверняка тоже пройдёт.

## Ветки

Одна долгоживущая ветка — `main`, всегда рабочая. Любое изменение — короткая ветка и PR:

```bash
git switch -c reader/word-tap
# работа
git push -u origin reader/word-tap
gh pr create --fill
```

После слияния в `main` изменения автоматически уезжают на dev-стенд.

Прямой push в `main` закрыт намеренно — даже в одиночку. PR даёт три вещи: гейт CI перед попаданием в главную ветку, preview-ссылку для проверки в браузере и внятную историю «зачем это было сделано», которую через полгода уже не восстановить по памяти.
