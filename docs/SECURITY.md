# Правила безопасности (публичный репозиторий)

Репозиторий Fluenta **ПУБЛИЧНЫЙ**. Никакие ключи, секреты и личные данные не должны попадать в код, коммиты или историю.

**Почему это критично:** утечка секрета в публичный репо = мгновенная компрометация (боты сканируют GitHub за секунды); git-история хранит секрет **навсегда**, даже после удаления из файла — приходится ротировать ключ. Личные данные (email, продовые IP, имена) в публичном репо — это приватность и лишняя attack surface.

## Что НИКОГДА не коммитить

- API-ключи (Gemini, OpenAI, любые LLM), пароли БД, JWT / session secrets.
- Приватные SSH-ключи (напр. `~/.ssh/fluenta_hetzner`), OAuth client secrets, токены.
- `.env` с реальными значениями, продовые IP / хосты, персональные email.
- Инфраструктурные детали → держим в `INFRA.local.md` (gitignored).

## Как обращаться с секретами

- **Только через env:** реальные значения в `.env` (в `.gitignore`); в репо — лишь `.env.example` с плейсхолдерами.
- На сервере — через `env_file` docker-compose (не в репо) или secret manager.
- IaC/провижн-секреты вне репо; если IaC коммитится — шифровать (SOPS / Ansible Vault / age).

## `.gitignore` обязан покрывать

`.env`, `.env.*` (кроме `.env.example`), `*.pem`, `*.key`, `id_*`, `*_rsa`, `*_ed25519`, `secrets/`, `credentials*`, `*.p12`, `*.local.md`, `*.local`, `node_modules/`, build-артефакты.

## Сканер секретов (обязательно)

- Поставить **gitleaks** (или trufflehog / git-secrets) как **pre-commit hook** + в CI — чтобы секрет физически не мог уйти в коммит.

## Если секрет всё же закоммичен

1. **Сразу ротировать** (сгенерировать новый ключ/пароль) — не полагаться на удаление из истории.
2. При необходимости чистить историю (`git filter-repo`), но ротация первична.

## Прочее

- README / доки / скриншоты — без реальных креды, токенов, продовых IP.
- Коммиты подписывать (GPG / SSH signing) желательно.
- Не светить приватный email — использовать GitHub noreply email.
