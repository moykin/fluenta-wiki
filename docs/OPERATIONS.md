# Окружения, деплой, эксплуатация

> Живой документ. Обновлять при каждом изменении в контуре деплоя. Обновлено: **2026-07-31**.

## Три окружения

| | Локально | Dev-стенд | Прод |
|---|---|---|---|
| Маркетинг | `make web` | preview-URL Cloudflare на каждый PR | `fluenta.wiki` |
| Приложение | `make app-web` | preview-URL Cloudflare | `app.fluenta.wiki` |
| API | `127.0.0.1:8000` | `api-dev.fluenta.wiki` | `api.fluenta.wiki` |
| База | Docker, порт 5433 | база `fluenta_dev` | база `fluenta` |
| Обновляется | вручную | автоматически при слиянии в `main` | вручную, с подтверждением |
| Данные | выбрасываемые | тестовые | боевые |

Фронт (маркетинг и Flutter web) — статика на **Cloudflare Pages**: глобальный CDN, ноль нагрузки на сервер, preview на каждый PR. Сервер держит только API и голосовой релей.

## Раскладка доменов

| Хост | Что | Где | Cloudflare |
|---|---|---|---|
| `fluenta.wiki`, `www` | маркетинг, SEO | Pages | проксируется |
| `app.fluenta.wiki` | приложение | Pages | проксируется |
| `api.fluenta.wiki` | API прод | сервер | **только DNS** |
| `api-dev.fluenta.wiki` | API dev | сервер | **только DNS** |

API-поддомены идут мимо прокси Cloudflare сознательно: голосовой тьютор — это долгие WebSocket-сессии, где каждый лишний сетевой хоп добавляется к задержке, а сервер и так в Орегоне. Плата за это — IP сервера виден, поэтому его прикрывают файрвол Hetzner, UFW и fail2ban. На Э2 задержку измерим и, если разница окажется незначимой, прокси можно будет включить и спрятать IP.

## Dev и прод на одной машине

Оба стека живут на одном CPX21. Чтобы dev не мог навредить проду:

- **Разные базы и разные пользователи.** У `fluenta_dev` нет прав на боевую базу — это отбирается явным `REVOKE` при инициализации.
- **Разные секреты.** Свой `JWT_SECRET` и отдельный ключ Gemini с меньшей квотой: эксперименты на dev не выжигают боевой бюджет.
- **Лимиты памяти.** Прод 1 ГБ, dev 640 МБ, Postgres 768 МБ, Caddy 128 МБ. Утечка на dev упрётся в свой лимит, а не съест память у прода.
- **Dev закрыт паролем** (basic auth) и отдаёт `X-Robots-Tag: noindex` — иначе Google проиндексирует dev-копию и уронит SEO прода дублями.

## Деплой

**На dev — автоматически.** Слияние PR в `main` запускает сборку образа, публикацию в GHCR, миграции и перезапуск сервиса.

**На прод — вручную:**

```bash
make deploy-prod          # или через вкладку Actions в GitHub
```

Прод-окружение защищено правилом подтверждения: workflow останавливается и ждёт нажатия кнопки.

Что происходит при выкатке: сборка образа → проверка Trivy на уязвимости (критические ломают деплой) → публикация → копирование конфигурации на сервер → `alembic upgrade head` → перезапуск → ожидание healthcheck. **Если сервис не стал здоровым за 150 секунд — автоматический откат на предыдущий тег.** После этого workflow отдельно проверяет, что сервис отвечает снаружи.

## Откат вручную

```bash
ssh <сервер>
cd /opt/fluenta
sed -i 's|^PROD_TAG=.*|PROD_TAG=sha-<предыдущий>|' .env
docker compose up -d api-prod
```

Список доступных тегов — на странице пакета `fluenta-api` в GHCR.

## Первичная настройка сервера

```bash
scp infra/provision.sh root@<ip>:/tmp/
ssh root@<ip> 'bash /tmp/provision.sh'
```

Скрипт идемпотентный. Делает: пользователя `deploy`, вход только по ключу, запрет root-логина, UFW, fail2ban, автообновления безопасности, Docker. **Перед выходом из root-сессии обязательно проверьте вход как `deploy`** — иначе можно закрыть себе доступ.

Дальше вручную: положить `/opt/fluenta/.env` по образцу `infra/.env.example` с правами 600, направить DNS, `docker compose up -d`.

## Секреты в GitHub

| Секрет | Зачем |
|---|---|
| `SSH_HOST`, `SSH_USER`, `SSH_KEY` | доступ для деплоя (отдельный ключ, не ваш личный) |
| `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` | публикация на Pages |

Ключи Gemini и JWT в GitHub **не хранятся** — они живут только в `/opt/fluenta/.env` на сервере.

## Резервные копии

- **Hetzner backups** — включить до появления первых боевых данных (+20%, ≈ €7.50/мес).
- **Дамп базы** — `pg_dump` по расписанию с выгрузкой за пределы сервера. Бэкап, лежащий на том же диске, не защищает от потери диска.
- Восстановление проверять на dev — непроверенный бэкап не считается бэкапом.

## Наблюдение

- `/healthz` на обоих API + внешний аптайм-чек.
- Логи ограничены (10 МБ × 3 файла на сервис) — диск не забьётся.
- Отдельно логировать задержку и стоимость вызовов LLM: это одновременно и метрика качества, и статья расходов.
